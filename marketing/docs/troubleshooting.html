Troubleshooting

When something's not syncing, start here.

Daemon not starting

The binary didn't download

On first run, scripts/start.mjs downloads the daemon binary from GitHub Releases and places it at ~/.claude/bin/crabtalk-daemon (or crabtalk-daemon.exe on Windows). If your machine has no internet access at startup, or GitHub was temporarily unavailable, the download fails silently and the plugin runs without the daemon.

Check whether the binary exists:

# macOS / Linux
ls ~/.claude/bin/crabtalk-daemon

# Windows (PowerShell)
Test-Path "$env:USERPROFILE\.claude\bin\crabtalk-daemon.exe"

If it's missing, restart Claude Code with internet access and it will retry. Or install manually — see Manual installation below.

The binary isn't executable (macOS / Linux)

The download script sets the executable bit automatically, but sometimes extraction strips it.

chmod +x ~/.claude/bin/crabtalk-daemon

macOS Gatekeeper block

macOS may quarantine the downloaded binary because it's not notarized. If you see "crabtalk-daemon cannot be opened because it is from an unidentified developer": 

xattr -d com.apple.quarantine ~/.claude/bin/crabtalk-daemon

Windows Defender block

Unsigned Rust binaries are occasionally flagged by Windows Defender on first execution. If the daemon fails to start silently on Windows, check Windows Security → Protection History. You may need to add %USERPROFILE%\.claude\bin\ to the exclusion list.

Peers not connecting

Check daemon status

Run in a Claude Code session:

/crabtalk:status

The output shows your peer ID, listen addresses, and the list of currently connected peers. If connected peers is empty but you've set up multiple machines, work through the checks below.

Both machines must be running

The daemon only connects to online peers. If machine B is asleep or Claude Code isn't running, machine A won't show it as connected. This is expected — sync resumes automatically when B comes back online.

Rendezvous registration

The daemon re-registers its addresses every five minutes. If a machine just woke up from sleep, wait up to five minutes for both peers to re-register and reconnect, or force an immediate sync: 

/crabtalk:sync-now

Firewall blocking QUIC

CrabTalk uses QUIC (UDP) for peer-to-peer connections. Some corporate firewalls or VPNs block outbound UDP entirely. If you're on a restricted network, mDNS (LAN discovery) may still work for machines on the same subnet, but WAN connections through the rendezvous server will fail. There is currently no TCP fallback.

Both machines on the same account

Devices only sync with peers registered to the same CrabTalk account. Verify with:

/crabtalk:status

The device name and account ID should match what you see at claw.crabtalk.dev.

Sync not working

File is excluded

CrabTalk skips hidden files (names starting with .) and node_modules/ directories. If you want to sync a dotfile outside ~/.claude/, it's not currently supported.

Conflict blocking the file

A conflicted file won't be overwritten until you resolve it. List conflicts with:

/crabtalk:list-conflicts

Then resolve each one:

# keep local version
/crabtalk:resolve-conflict {"path": "CLAUDE.md", "resolution": "local"}

# keep remote version
/crabtalk:resolve-conflict {"path": "CLAUDE.md", "resolution": "remote"}

Daemon restarted and lost state

If the daemon crashes and restarts while a sync is in progress, the partial transfer is abandoned. Run /crabtalk:sync-now to re-initiate from the manifest comparison.

Manual installation

If the auto-download fails, you can install the daemon binary by hand from the GitHub Releases page.

Download the archive for your platform:

crabtalk-daemon-x86_64-linux.tar.gz    # Linux x86
crabtalk-daemon-aarch64-linux.tar.gz   # Linux ARM64
crabtalk-daemon-x86_64-macos.tar.gz    # macOS Intel
crabtalk-daemon-aarch64-macos.tar.gz   # macOS Apple Silicon
crabtalk-daemon-x86_64-windows.zip     # Windows x86
crabtalk-daemon-aarch64-windows.zip    # Windows ARM64

Extract it and place the binary at ~/.claude/bin/:

# macOS / Linux
mkdir -p ~/.claude/bin
tar -xzf crabtalk-daemon-*.tar.gz -C ~/.claude/bin/
chmod +x ~/.claude/bin/crabtalk-daemon

# Windows (PowerShell)
New-Item -ItemType Directory -Force "$env:USERPROFILE\.claude\bin"
Expand-Archive crabtalk-daemon-*.zip -DestinationPath "$env:USERPROFILE\.claude\bin" -Force

Restart Claude Code — the plugin will detect the binary and start the daemon.

Still stuck?

Open an issue on GitHub and include the output of /crabtalk:status. The daemon logs to stderr, which gets captured in the Claude Code MCP server logs.

Self-hosting the rendezvous server

If you hit rate limits or want to run your own infrastructure, the rendezvous server is a plain Cloudflare Worker. Deploy it yourself and set CRABTALK_SIGNAL_URL in .mcp.json to your own endpoint.
